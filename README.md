# Род Матюхиных и Скиба — семейный архив

**Live:** https://smaturus.github.io/family-history/

Статический генератор семейного архива: локальные данные в YAML, проверенные архивные дополнения и редактируемые тексты преобразуются в сайт с летописью, ономастикой, географией и SVG-древом.

Подробнее:

- [docs/architecture.md](docs/architecture.md) — слои данных, схема сборки, privacy-by-design, публикация в Pages;
- ADR (архитектурные решения) ведутся локально и в публичный репозиторий не входят.

---

## Возможности

- **Летопись** — четыре родовые линии, таймлайн поколений, блок «точка встречи» двух ветвей
- **Ономастика и география** — частые фамилии и места рода с пояснениями
- **SVG-древо** — прямые предки с пометками «гипотеза / нет данных»; карточка без плашки — запись в семейной базе (не документальное подтверждение)
- **Карта поиска** — приоритетные «белые пятна» в прямой линии
- **Редактируемые тексты** — заголовки и абзацы в `content/content.yaml` без правок Python

---

## Источники данных

Три слоя: **YAML-данные** (`data/family.yaml` — персоны, даты, связи; хранится только локально, для живых — только имена и годы рождения), **архивные дополнения** (ревизия 1834 г., OCR + ручная проверка — внесены в YAML как обычные персоны) и **YAML-тексты** (`content/content.yaml` — редакционные тексты). ИИ используется только как инструмент чтения скорописи, не как источник фактов.

## Технологии

- Python 3, PyYAML
- Статический HTML, CSS и SVG
- pytest — тесты загрузчика данных/приватности и a11y собранного сайта
- GitHub Actions: `ci.yml` (тесты + smoke-сборка на фикстуре) и Pages

## Структура репозитория

```
├── data/
│   └── family.yaml              # локальные данные семейного архива (НЕ коммитится, игнорируется Git)
├── content/
│   └── content.yaml             # редактируемые тексты сайта
├── scripts/
│   ├── parse_data.py            # загрузка family.yaml: модель персон, валидация, приватный предохранитель
│   ├── build_site.py            # генератор index.html: рендер секций, валидация YAML, privacy-проверка
│   ├── extract_data.py          # одноразовый миграционный скрипт: извлечение данных из index.html
│   └── grade_hero_bg.py         # офлайн-регрейд hero-фона (нужны numpy и Pillow — см. requirements-dev.txt)
├── tests/
│   ├── fixtures/minimal.yaml   # синтетическая фикстура для тестов и CI (вымышленные люди)
│   ├── test_parser.py          # pytest: загрузчик YAML, приватность, сборка
│   └── test_a11y.py            # pytest: a11y собранного HTML (title/desc, tabindex, aria)
├── assets/
│   ├── site.css                 # стили (инлайнятся в index.html при сборке)
│   ├── Image 1.png / Image 2.png  # мастер фона hero и референс раскладки (в Pages не публикуются)
│   └── hero-bg*.{avif,webp,jpg} # производные фона — входят в allowlist публикации
├── docs/
│   └── architecture.md          # архитектура и инженерные решения
├── index.html                   # собранный сайт (коммитится после локальной сборки)
├── .github/workflows/
│   ├── ci.yml                   # тесты + smoke-сборка на фикстуре (без реальных данных)
│   └── pages.yml                # публикация allowlist-файлов в gh-pages
├── .nojekyll                    # отключает Jekyll на Pages
├── LICENSE                      # MIT для кода
├── requirements.txt             # рантайм-зависимости сборщика (PyYAML)
└── requirements-dev.txt         # для разработки: pytest, numpy, Pillow
```

## Быстрый старт

```bash
# 1. Восстановите локальные данные (data/family.yaml не хранится в Git)
python3 scripts/extract_data.py        # извлечёт данные из index.html в data/family.yaml

# 2. Установите зависимости и соберите сайт
python3 -m pip install -r requirements.txt
python3 scripts/build_site.py

# 3. Локальный просмотр
python3 -m http.server 8080
# → http://localhost:8080
```

Персоны, даты и связи правятся прямо в `data/family.yaml`; сборщик проверяет уникальность id, ссылки отец/мать и приватность (живым — только год рождения).

### Разработка и тесты

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m pytest tests/ -q
```

CI (`ci.yml`) гоняет те же тесты и smoke-сборку на синтетической фикстуре при каждом push/PR в `master`; реальные данные в Actions не попадают (подробнее — ADR «CI-сборка на фикстуре», ведутся локально).

### Редактирование текстов

1. Правки в `content/content.yaml`
2. `python3 scripts/build_site.py`
3. Коммит `content/content.yaml` и `index.html` → merge в `master`

## Публикация

После merge в `master` workflow [`.github/workflows/pages.yml`](.github/workflows/pages.yml) автоматически обновляет `gh-pages`, публикуя только `index.html`, `.nojekyll` и оптимизированные варианты `assets/hero-bg*`.

## Ограничения и приватность

Для ныне живущих публикуются только имя и год рождения — это правило зашито и в сами данные (`data/family.yaml`), и в загрузчик: `parse_data.py` падает с понятной ошибкой, если живому человеку вписать точную дату или место. Сам файл `family.yaml` хранится **только локально на машине автора** и не публикуется в открытом репозитории из соображений приватности — даже в виде имён и годов живых людей. Сборка дополнительно проверяет, что точные даты живых не утекли в HTML. Любые сторонние выгрузки семейного древа в репозиторий не попадают — в них уровни приватности ниже. Сборка выполняется локально, CI работает на фикстуре с вымышленными людьми, публикация ограничена allowlist-файлами. Подробные правила — в [docs/architecture.md](docs/architecture.md#инженерные-решения).
