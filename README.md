# Род Матюхиных и Скиба — семейный архив

**Live:** https://smaturus.github.io/family-history/

Статический генератор семейного архива: локальный GEDCOM-экспорт, проверенные архивные дополнения и редактируемые тексты преобразуются в сайт с летописью, ономастикой, географией и SVG-древом.

В перспективе проект будет разделён на общий хаб (family-history) и отдельные ветви: skiba-history и matyukhin-history.

Подробнее:

- [docs/architecture.md](docs/architecture.md) — слои данных, схема сборки, privacy-by-design, публикация в Pages;
- [docs/decisions.md](docs/decisions.md) — краткие ADR: hero и ассеты, данные и сборка, публикация, лицензирование.

---

## Возможности

- **Летопись** — четыре родовые линии, таймлайн поколений, блок «точка встречи» двух ветвей
- **Ономастика и география** — частые фамилии и места рода с пояснениями
- **SVG-древо** — прямые предки с пометками «подтверждено / гипотеза / нет данных»
- **Карта поиска** — приоритетные «белые пятна» в прямой линии
- **Редактируемые тексты** — заголовки и абзацы в `content/content.yaml` без правок Python

---

## Источники данных

Три слоя: **GEDCOM** (структурированная основа), **архивные дополнения** (ревизия 1834 г., OCR + ручная проверка) и **YAML** (редакционные тексты). ИИ используется только как инструмент чтения скорописи, не как источник фактов.

## Структура репозитория

```
├── data/                        # GEDCOM-экспорт (skiba.ged) — создаётся локально, в Git не попадает
├── content/
│   └── content.yaml             # редактируемые тексты сайта
├── scripts/
│   ├── parse_gedcom.py          # парсер GEDCOM, фильтр приватности, архивные вставки (1834 г.)
│   ├── build_site.py            # генератор index.html: рендер секций, валидация YAML, privacy-проверка
│   └── grade_hero_bg.py         # офлайн-регрейд hero-фона (нужны numpy и Pillow, не входят в requirements)
├── assets/
│   ├── site.css                 # стили (инлайнятся в index.html при сборке)
│   ├── Image 1.png / Image 2.png  # мастер фона hero и референс раскладки (в Pages не публикуются)
│   └── hero-bg*.{avif,webp,jpg} # производные фона — входят в allowlist публикации
├── docs/
│   ├── architecture.md          # архитектура и инженерные решения
│   └── decisions.md             # ADR, кратко
├── index.html                   # собранный сайт (коммитится после локальной сборки)
├── .github/workflows/pages.yml  # публикация allowlist-файлов в gh-pages
├── .nojekyll                    # отключает Jekyll на Pages
├── LICENSE                      # MIT для кода
└── requirements.txt             # рантайм-зависимости сборщика (PyYAML)
```

## Быстрый старт

```bash
# 1. Положите экспорт MyHeritage в data/skiba.ged (файл не коммитится)
mkdir -p data
cp /путь/к/экспорту.ged data/skiba.ged

# 2. Установите зависимости и соберите сайт
python3 -m pip install -r requirements.txt
python3 scripts/build_site.py

# 3. Локальный просмотр
python3 -m http.server 8080
# → http://localhost:8080
```

Архивные поколения добавляются в `scripts/parse_gedcom.py`, поэтому замена GEDCOM не удаляет их автоматически.

### Редактирование текстов

1. Правки в `content/content.yaml`
2. `python3 scripts/build_site.py`
3. Коммит `content/content.yaml` и `index.html` → merge в `master`

---

## Публикация

После merge в `master` workflow [`.github/workflows/pages.yml`](.github/workflows/pages.yml) автоматически обновляет `gh-pages`, публикуя только `index.html`, `.nojekyll` и оптимизированные варианты `assets/hero-bg*`.

## Ограничения и приватность

GEDCOM содержит персональные данные ныне живущих людей и не хранится в репозитории. Для живых публикуются только имя и год рождения; сборка падает, если точная дата или место живого человека утекли в HTML. Ограничения, вытекающие из этого: сборка выполняется локально (GEDCOM не передаётся в CI), а публикация ограничена allowlist-файлами. Подробные правила — в [docs/architecture.md](docs/architecture.md#инженерные-решения).
