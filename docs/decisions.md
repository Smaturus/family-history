## Данные и сборка

| Решение | Почему |
|---------|--------|
| `data/family.yaml` — единственный источник данных, хранится только локально | Даже имена и годы живых людей — ПДн; файл не публикуется (см. ADR «Миграция на YAML с использованием частичного GEDCOM», дополнение) |
| `*.ged` не в Git (любые) | Privacy: в выгрузках точные даты и места живых людей |
| Сайт собирается локально; CI гоняет сборку только на фикстуре | Проверка генератора без реальных данных (см. ADR «CI-сборка на фикстуре») |
| Архивные предки 1834 г. — обычные персоны YAML | Были кодовой вставкой в парсере; теперь данные отделены от кода |
| YAML — тексты + данные | `content/content.yaml` — редакционные тексты, `data/family.yaml` — факты |

## ADR: Лицензирование кода и контента

- **Контекст:** репозиторий вырос из шаблона github-slideshow (MIT, © Thomas Friese, 2016) и переписан в генератор семейного архива (2026).
- **Решение:** сохранить MIT для кода с двумя copyright-строками (Thomas Friese + Smaturus); контент `content/` и генеалогические тексты — all rights reserved, без открытой лицензии; ПДн живых людей не коммитятся.
- **Последствия:** код можно форкать и переиспользовать; тексты и данные защищены; атрибуция исходного шаблона сохранена.

## ADR: Архитектура репозиториев и переименование

- **Контекст:** имя github-slideshow досталось от шаблона и не отражало суть проекта. В перспективе экосистема разделится на хаб и дочерние ветви: family-history (общий семейный архив), skiba-history (ветвь Скиба), matyukhin-history (ветвь Матюхиных).
- **Решение:** репозиторий переименован в family-history. Сейчас он содержит весь код и контент и позиционируется как зонтичный проект (хаб); разделение на отдельные репозитории отложено до появления практической необходимости.
- **Последствия:** URL сайта — https://smaturus.github.io/family-history/; ссылки на репозиторий в документации обновлены (упоминания github-slideshow как имени исходного шаблона в LICENSE и ADR сохранены намеренно). Впоследствии на главной странице family-history появятся ссылки на дочерние проекты. GitHub сам перенаправляет со старого имени репозитория, но полагаться на это не стоит.

## ADR: Статус древа без «Подтверждено»

- **Контекст:** плашка «Подтверждено» на карточках древа означала лишь наличие записи в GEDCOM-выгрузке MyHeritage, а не документальное подтверждение; при этом предки, установленные по ревизии 1834 г. (село Мокрое), помечены «Гипотеза» — иерархия статусов читалась наоборот, самый «сильный» ярлык соответствовал самому слабому доказательству.
- **Решение:** плашка дефолтного статуса (`ok`) убрана из `render_badge` и из легенды древа. Карточка без плашки = «есть в базе MyHeritage», легенда объясняет это явно («запись базы не является документальным подтверждением»); цвет рамки (сталь) сохранён. Точечные статусы «Гипотеза» и «Нет данных» не менялись. Текущий `index.html` приведён к этому виду механической трансформацией (см. ADR «Механическая трансформация артефакта») с проверкой эквивалентности данных.
- **Последствия:** слово «Подтверждено» больше не используется на сайте; ключ `tree.status.ok` в `content.yaml` сохранён (валидация схемы требует ok/hyp/q). После появления GEDCOM обычная пересборка воспроизведёт новый вид древа без ручных правок.

## ADR: Механическая трансформация артефакта

- **Контекст:** a11y-правки (SVG title/desc, tabindex, aria-current, reduced-motion) нужно было опубликовать на live-сайте, но GEDCOM в данный момент недоступен, а боевой `index.html` собирается только локально — полноценная пересборка невозможна.
- **Решение:** правки применены к существующему `index.html` побайтовой трансформацией (коммит `19a4cc1`) с доказательством эквивалентности данных: извлечение и сравнение имён (SVG `<text>` + таймлайн) и всех 4-значных годов до и после — мультимножества совпали один в один (266 вхождений годов, 32 имени). Генератор (`build_site.py`) уже содержит те же a11y-изменения, поэтому при появлении GEDCOM обычная локальная сборка воспроизведёт этот же результат, и трансформация станет обычным ребилдом.
- **Последствия:** live-сайт получил a11y-правки без пересборки; риск расхождений с будущей генераторной сборкой закрыт сверкой и идентичностью правок в генераторе. Метод подходит только для точечных, механически проверяемых изменений — любые содержательные правки данных через ручную правку HTML запрещены.

## ADR: Legacy hero-кода

- **Контекст:** в `scripts/build_site.py` остался блок ~870 строк (строки 959–1826: `_hero_limbs`, `_hero_facet_points`, `_hero_density`, `_hero_glow`, `_hero_veil`, `_hero_defs`, `render_hero_graph`) — процедурный SVG-генератор «созвездия» для первого экрана. `render_hero_graph` больше не вызывается: hero рендерится статически (`render_hero_section` поверх мастер-арта `Image 1.png` по раскладке `Image 2.png`, см. таблицу «Hero / первый экран»).
- **Решение:** код оставлен как legacy — возможно, пригодится для будущих экспериментов с дизайном (процедурные варианты фона без перерисовки арта). Он задокументирован здесь, чтобы новые контрибьюторы не принимали его за живой путь сборки и не тратили время на «мёртвую» ветку.
- **Последствия:** функция `render_hero_graph` и её хелперы не покрыты тестами и не влияют на CI; при рефакторинге `build_site.py` их можно удалить одним движением, не ломая ничего. Перед любым повторным использованием — ревизия и покрытие тестами.

## ADR: CI-сборка на фикстуре

- **Контекст:** реальные данные (`data/family.yaml`, ранее `data/skiba.ged`) содержат ПДн живых людей и не должны попадать в Actions, поэтому долгое время сборка в CI не выполнялась — поломки генератора обнаруживались только при локальной сборке, а инструменты ассетов (numpy, Pillow) вообще не были зафиксированы.
- **Решение:** CI (`ci.yml`) прогоняет `build_site.py` на синтетической фикстуре `tests/fixtures/minimal.yaml` с вымышленными людьми (ранее — `minimal.ged` с якорными ID `@I155@`/`@F59@` под inject-блок; якоря упразднены вместе с GEDCOM). Реальные данные в CI не попадают: фикстура подкладывается как `data/family.yaml` в рабочую копию, коммит не трогается. Боевой `index.html` собирается и коммитится локально. numpy и Pillow вынесены в `requirements-dev.txt` — сборщику они не нужны. Входные файлы проверяются до разбора: наличие, UTF-8, структура — с понятными сообщениями вместо трейсбеков.
- **Последствия:** поломки сборки и генератора ловятся в CI до merge; контракт фикстуры (meta/root/persons/families) проверяется тестами `tests/test_parser.py`. При изменении схемы family.yaml фикстуру нужно обновлять вместе с ней.

## ADR: Отказ от GEDCOM в пользу YAML

- **Контекст:** доступ к MyHeritage утерян, файл `data/skiba.ged` утерян; данные (имена, даты, связи, включая архивные предков 1834 года) остались только в сгенерированном `index.html` и в коде парсера. Ждать восстановления доступа было нельзя, а единственный непонятный для человека формат — GEDCOM — мешал править данные руками.
- **Решение:** все данные, механически извлекаемые из опубликованного HTML, перенесены в коммитимый `data/family.yaml`: персоны — из карточек SVG-древа и таймлайна, связи — из геометрии коннекторов (колонки поколений + `path.ln`), статусы — по классам карточек с перекрёстной проверкой вывода генератора. `build_site.py` читает YAML через новый `scripts/parse_data.py`, дающий ту же модель Person/Family, что раньше давал GEDCOM-парсер, — рендер-функции не менялись. Извлечение выполнено скриптом `scripts/extract_data.py` с проверками: каждая дата должна присутствовать в HTML, список карточек — совпадать один в один. Нерепроизводимые из HTML связи и персоны зафиксированы в разделе `gaps:`. Архивные предки 1834 года (Илья, Григорий, их жёны и дети) стали обычными персонами YAML без GEDCOM-идентификаторов.
- **Последствия:** проект не зависит от утерянных форматов и внешних баз; YAML редактируется руками; приватный фильтр переехал в `parse_data.py` (загрузка падает, если живому человеку вписать точную дату или место); тесты якорей `@I155@`/`@F59@` упразднены вместе с якорями; `scripts/parse_gedcom.py` удалён, `.gitignore` больше не упоминает `data/skiba.ged`. Часть «коммитимый» этого решения впоследствии пересмотрена в сторону приватности — см. дополнение в ADR «Миграция на YAML с использованием частичного GEDCOM».

## ADR: Миграция на YAML с использованием частичного GEDCOM

- **Контекст:** в ходе миграции в проекте обнаружен частичный GEDCOM (`data/partial.ged` — выгрузка MyHeritage SKIBA от 17.07.2026, 233 INDI / 90 FAM против опубликованных 243/93; 6 битых байт внутри одного NOTE). Файл закрывает часть пробелов, но коммитить его нельзя (точные даты и места живых), а строить рантайм на нём — значит сохранить зависимость от внешнего формата.
- **Решение:** GEDCOM использован только как разовый источник обогащения (`scripts/enrich_from_ged.py`): имена сопоставляются с YAML (первичный ключ «фамилия+имя», для опубликованных одноимён — по уникальному имени, для «Федота» — по документированной связи старого inject-блока); даты переносятся только при согласии годов, противоречия уходят в раздел `conflicts:` с приоритетом index.html; боковые родственники добавляются все (190 персон) с пометкой `source: ged` и приватным фильтром (живым — только год рождения, без мест); родительские связи карточек древа не трогаются, чтобы опубликованное древо не «поплыло» (перестроенный HTML побайтово совпал с опубликованным). Абсурдные даты-склейки выгрузки (смерть на 147–155 лет позже точки отсчёта) отбрасываются с фиксацией в `conflicts:`. Служебные записи (`Unassociated photos`) и безымянные заглушки не переносятся. После миграции скрипт удаляется; `*.ged` добавлен в `.gitignore`.
- **Последствия:** `data/family.yaml` — 240 персон (50 из HTML + 190 из GED), 3 раздела gaps закрыты (сыновья Захарова-Алексеева, дети Васильевых, родня по браку — частично); известные расхождения зафиксированы (8 записей в `conflicts:`), а не потеряны; «мать не найдена» у Андрея Федотовича подтверждена выгрузкой (Параскевы Петровой в GED нет); оставшиеся gaps — места и персональный состав 10 персон, отсутствующих в частичном файле.
- **Дополнение (25.10.2026, решение пользователя):** `data/family.yaml` НЕ коммитится. Изначально YAML задумывался коммитимым (живые — только имя и год рождения), но при финальной проверке принято решение о полной приватности: сам список из 240 имён и годов — уже персональные данные. Файл добавлен в `.gitignore` и хранится только локально; в открытом репозитории остаются код, тесты, документация, тексты и собранный `index.html`. CI собирает сайт на синтетической фикстуре `tests/fixtures/minimal.yaml`. Путь восстановления после утери локального файла — `scripts/extract_data.py` из опубликованного `index.html`. Одновременно с этим формулировки «MyHeritage»/«GEDCOM» в текстах сайта заменены на «семейная база» (hero, «Источник», «Что откуда взято», легенда древа, футер).
