# Архитектура и инженерные решения

Подробное описание слоёв данных, сборки и публикации семейного архива. Краткий обзор — в [README](../README.md); фиксированные решения — в [decisions.md](decisions.md).

---

## Схема сборки

```
data/family.yaml          ──►  parse_data.py    ──┐
  (локально, не в Git;           (валидация,           │
   персоны, даты, связи,         приватный фильтр)     ├──►  build_site.py  ──►  index.html
   database, gaps, conflicts)                          ▲
content/content.yaml    ──────────────────────────────┘
assets/site.css         ─────────────────────────────────────────┘
                                                          │
merge в master ──► GitHub Actions ──► gh-pages ──► GitHub Pages
                                      (только index.html, .nojekyll
                                       и assets/hero-bg*.{avif,webp,jpg})
```

| Слой | Источник | Ответственность |
|------|----------|-----------------|
| **Данные** | `data/family.yaml` + `scripts/parse_data.py` | Имена, даты, связи, статусы; валидация ссылок и приватности; агрегаты утерянной базы (`database`) |
| **Контент** | `content/content.yaml` | Заголовки, абзацы, очерки линий, подписи, легенда |
| **Генератор** | `scripts/build_site.py` | Модульный рендер секций, SVG-древо, валидация YAML, post-build проверка приватности |
| **Публикация** | `.github/workflows/pages.yml` | Деплой только статических файлов в `gh-pages` |

## Источники данных

Опубликованные сведения складываются из трёх слоёв. Слои различаются способом получения и степенью доказанности, поэтому разделены и в коде, и в подаче на сайте.

**1. Структурированная основа — `data/family.yaml`.** Единственный источник фактов: персоны (имя, фамилия, даты, статус), родственные связи (ссылки отец/мать), семьи (браки), агрегаты базы (`database`) и честный список того, что не удалось извлечь (`gaps:`) и что разошлось с прежними источниками (`conflicts:`). Файл правится руками, но **не публикуется**: он хранится только локально на машине автора и исключён из Git из соображений приватности (см. ADR «Миграция на YAML с использованием частичного GEDCOM») — в открытом репозитории остаются только код, тексты, тесты и собранный `index.html`. Восстановление после утери — скриптом `scripts/extract_data.py` из опубликованного `index.html`. Происхождение: механическое извлечение из опубликованного `index.html` (ADR «Отказ от GEDCOM в пользу YAML») с последующим обогащением из найденного частичного GEDCOM (ADR «Миграция на YAML с использованием частичного GEDCOM») — 240 персон, из них 190 перенесены из выгрузки с пометкой `source: ged`.

**2. Архивные дополнения.** Часть предков установлена по постранично отснятым архивным делам — прежде всего по ревизской сказке 1834 года по селу Мокрое Белевского уезда Тульской губернии (двор №26). Распознавание скорописи и сопоставление записей выполнялись с помощью ИИ (OCR и разбор рукописного текста); прочтения проверялись вручную и лишь затем вносились в данные:

- **персоны и связи** — в `data/family.yaml` как обычные персоны (Илья, Григорий, их жёны и дети) с примечаниями, цитирующими реквизиты дела; связь Федота с ревизией отражена в примечаниях, а не в GEDCOM-якорях, которых больше нет.
- **формулировки и оговорки** — текстами в `content/content.yaml`: очерк линии Матюхиных с реквизитами дела, примечания к фамилиям и местам, легенда древа «гипотеза / нет данных» (карточки без плашки — запись в семейной базе, см. ADR «Статус древа без „Подтверждено"»).

ИИ и OCR здесь — исследовательский инструмент чтения источника, а не самостоятельный источник и не автор выводов. Чтения, не подтверждённые документом, помечены на сайте как гипотезы; фамилия Матюхин для поколений 1834 года сознательно не утверждается, потому что в ревизии она не записана.

**3. Редакционный слой — YAML-тексты.** `content/content.yaml` отвечает за подачу: заголовки, вводные абзацы, очерки линий, примечания, подписи и легенду. Числа, даты и цепочки поколений в нём не дублируются — их считает генератор из слоёв 1 и 2.

Правила приватности применяются к первому слою. Архивные персоны — люди XVIII–XIX веков, под ограничение не попадают.

## Инженерные решения

**Privacy-by-design.** Для ныне живущих в `data/family.yaml` хранятся только имя и год рождения — и даже этого мало для публикации: файл целиком остаётся локальным (`.gitignore`), потому что сам по себе список из 240 имён и годов — это персональные данные живых людей. Приватность проверяется при загрузке: `parse_data.py` падает с понятной ошибкой, если живому человеку вписать точную дату или место рождения. Правило то же, что раньше применялось к GEDCOM: сборка дополнительно проверяет, что точные даты живых не утекли в HTML. Любые GEDCOM-выгрузки (`*.ged`) содержат больше ПДн и в репозиторий не попадают.

**Разделение данных и текстов.** `data/family.yaml` формирует факты, `content/content.yaml` — только редакционные тексты без `{плейсхолдеров}`. Персоны, даты и связи правятся в данных, а не в коде: `scripts/parse_data.py` строит из YAML ту же модель Person/Family, что раньше строил GEDCOM-парсер, поэтому рендер-функции генератора не знают о формате хранения.

**Валидация YAML.** `build_site.py` проверяет обязательные ключи и типы в `content/content.yaml` и `data/family.yaml` (уникальность id, существование ссылок отец/мать, статус ok/hyp) и падает с понятным сообщением, если структура нарушена.

**Тесты и CI.** Логика загрузчика данных, приватный предохранитель и a11y собранного HTML (SVG title/desc, tabindex, aria-атрибуты, reduced-motion) покрыты pytest-тестами в `tests/` (17 тестов). Workflow `ci.yml` прогоняет их при каждом push/PR в `master`, затем выполняет smoke-сборку сайта на синтетической фикстуре `tests/fixtures/minimal.yaml` с вымышленными людьми и проверяет целостность вывода. Подробнее — ADR «CI-сборка на фикстуре» в [decisions.md](decisions.md).

**Безопасная публикация.** Workflow публикует в `gh-pages` только allowlist: `index.html`, `.nojekyll` и производные фона первого экрана `assets/hero-bg{,-768,-1280}.{avif,webp,jpg}`. CSS инлайнится при сборке; исходный **hero background** (`assets/Image 1.png`) в Pages не попадает — отдаются только сжатые responsive-варианты, а не base64 и не исходный PNG. Данные, Python-скрипты и исходные изображения на live-сайт не уходят.

**Ассеты первого экрана.** Фон — мастер `assets/Image 1.png`; раскладка заголовка, навигации и дат сверстана по референсу `assets/Image 2.png`. В прод уходят только производные AVIF → WebP → JPEG (ширины 768 / 1280 / 1376) с preload LCP-кандидата.

**Осознанный trade-off.** Боевая сборка выполняется локально: CI работает на синтетической фикстуре, чтобы ловить поломки генератора до merge, не касаясь реальных данных. Перед merge в `master` обновлённый `index.html` коммитится вручную после локальной пересборки.

## Публикация

После merge в `master` workflow [`.github/workflows/pages.yml`](../.github/workflows/pages.yml) автоматически обновляет `gh-pages`.

**Требования к репозиторию (один раз):**

- `Settings` → `Actions` → `General` → **Read and write permissions** для workflow
- Ветка `gh-pages` не должна блокировать force-push от GitHub Actions

Файл `.nojekyll` отключает обработку Jekyll на GitHub Pages и нужен, чтобы статический `index.html` и ассеты отдавались как есть.

## Структура репозитория

| Путь | Назначение |
|------|------------|
| `data/family.yaml` | Локальные данные семейного архива: персоны, связи, статусы, агрегаты базы, gaps и conflicts (НЕ коммитится, игнорируется Git) |
| `content/content.yaml` | Редактируемые тексты сайта |
| `scripts/parse_data.py` | Загрузчик YAML: модель персон/семей, валидация, приватный предохранитель |
| `scripts/extract_data.py` | Одноразовый миграционный скрипт: извлечение данных из index.html в YAML |
| `scripts/enrich_from_ged.py` | Одноразовый миграционный скрипт: обогащение YAML из найденного частичного GEDCOM |
| `scripts/build_site.py` | Генератор `index.html`: `render_*` секции, валидация YAML, post-build проверка |
| `assets/site.css` | Стили (инлайнятся в HTML при сборке) |
| `assets/Image 1.png`, `assets/Image 2.png` | Мастер фона первого экрана и референс раскладки (в Pages не публикуются) |
| `assets/hero-bg*.{avif,webp,jpg}` | Оптимизированные производные фона первого экрана — входят в allowlist `gh-pages` |
| `index.html` | Собранный сайт (коммитится в `master`) |
| `tests/` | pytest-тесты (загрузчик, приватность, a11y) и синтетическая фикстура `minimal.yaml` |
| `requirements.txt` | Рантайм-зависимости сборщика |
| `requirements-dev.txt` | Зависимости разработки: pytest, numpy, Pillow |
| `.github/workflows/ci.yml` | Тесты + smoke-сборка на фикстуре при push/PR |
| `.github/workflows/pages.yml` | Автопубликация в `gh-pages` |
| `.nojekyll` | Отключает обработку Jekyll на GitHub Pages |
